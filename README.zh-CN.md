# 软件集群作业技能：Slurm 与 PBS

[English](README.md)

用自然语言告诉代理你想运行什么计算，它会帮助你把任务交给远程集群运行、查看进度并整理结果。可以把集群理解为一组供大家使用的计算机，把 Slurm 或 PBS 理解为负责排队和分配资源的管理员。

仓库提供三个配合使用的指令型技能。代理按实际软件和任务生成脚本；仓库不附带开箱即用的计算程序，也不会替你申请集群账号或安装计算软件。

| 技能 | 用途 |
|---|---|
| `software-hpc-run` | 通用入口：识别目标集群，选择对应技能 |
| `software-slurm-run` | 在确认使用 Slurm 的集群上准备、提交、查询和收尾 |
| `software-pbs-run` | 在确认使用 PBS 的集群上处理同样的工作 |

建议一起安装三个技能。PBS 流程以 OpenPBS/PBS Professional 为基础；其他 PBS 变体需要核对平台说明。单节点、多节点、MPI、多线程及混合并行均按软件和集群支持情况选择。

## 小白使用指南

### 1. 先准备这些信息

- 已安装并登录的 Codex CLI。还没有安装时，先按 [Codex CLI 官方指南](https://learn.chatgpt.com/docs/codex/cli)操作。
- 平台或管理员提供的集群账号及连接说明，以及使用计算资源的权限。
- 集群上可用的软件和适用的许可证。
- 你要计算的输入文件，以及希望保存结果的位置。

不清楚计费账户、队列、分区或资源数量，可以先让代理查询。查不到时，代理应明确告诉你需要向管理员询问什么。初次使用不需要先学会 MPI。

### 2. 在 Codex 中安装三个技能

**自己电脑的终端中输入：**

```bash
codex
```

如果提示找不到 `codex`，先完成上一节的安装。进入 Codex 后，下面的文字要发到 **Codex 对话框**，不要当成终端命令执行：

```text
$skill-installer
请从 https://github.com/Raining-Sunshine/SAI-agent-job-submit-skill 安装以下三个技能：
skills/software-hpc-run
skills/software-slurm-run
skills/software-pbs-run
如果已有同名技能，请先检查本地改动，再更新为仓库版本。
```

安装完成后，在 Codex 中输入 `/skills`，确认三个技能都能找到。若没有显示，重新启动 Codex。技能的安装和调用方式参见 [Codex 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

### 3. 配置并测试集群连接

已有可用的 SSH 别名时直接使用它。首次配置可参考下面的最小示例，将它写入**本机 OpenSSH 的用户配置文件**；Linux/macOS/WSL 通常使用 `~/.ssh/config`。这是配置内容，不是一组要执行的命令。

```sshconfig
Host cluster
    HostName <HOST>
    User <USER>
    Port <PORT>
    IdentityFile <KEY_FILE>
    IdentitiesOnly yes
```

| 内容 | 如何填写 |
|---|---|
| `cluster` | 你给这条连接起的简称；后续告诉代理这个简称 |
| `<HOST>` | 平台提供的登录服务器地址 |
| `<USER>` | 你的集群登录用户名 |
| `<PORT>` | 平台提供的 SSH 端口 |
| `<KEY_FILE>` | 本机所用密钥文件的位置，不是密钥内容 |

把占位符连同尖括号一起替换。按平台说明核对首次连接的主机身份，并在自己的终端完成密钥解锁。使用不同认证方式时，沿用平台提供的配置。

**在运行 Codex 的同一本机环境中测试：**

```bash
ssh cluster exit
```

正常返回且没有错误表示 SSH 连接可用，尚不代表有作业提交权限。若提示找不到主机、连接超时或认证失败，先按平台连接说明解决。代理使用连接别名，无需读取密钥材料或许可证内容。

### 4. 让代理检查环境并准备第一次任务

在 **Codex 对话中**发送下面的请求，将各项补成自己的信息：

```text
我第一次使用集群计算技能，请自动判断应该使用 Slurm 还是 PBS。

集群连接别名：……
我要使用的软件：……
输入文件目前在：本机／服务器，位置是……
我希望完成的计算：……
结果希望保存在：……

请先检查连接、软件和运行条件，暂不提交作业。
资源参数如果可以查询，请帮我检查并建议；
无法确定的内容，请告诉我需要向管理员询问什么。
```

自然语言请求可以触发已安装的技能。如果代理没有选中，可以在请求开头加上 `$software-hpc-run`。

代理会在目标集群做只读检查，然后选择 Slurm 或 PBS 技能。两种系统都存在、访问失败或证据不足时，它会说明情况并询问必要信息，不会用提交测试作业的方式猜测。已知系统的用户也可直接调用 `$software-slurm-run` 或 `$software-pbs-run`。

输入文件还在本机时，代理先确认远端目标位置，再按任务需要上传；已经在服务器时使用现有文件。上传完成后才准备计算。可先使用临时文件名，完成后改名，保留软件要求的格式。原件保留，结果另存。

这一步完成后，你应看到：检测到的调度系统、软件是否可用、输入检查结果、拟申请的资源和最长运行时间，以及仍需补充的信息。资源方案应说明节点数、进程/线程数、内存总量及其分配方式。

### 5. 确认方案后提交

仍在 **Codex 对话中**输入：

```text
按刚才确认的方案提交这次作业，并告诉我作业号和当前状态。
```

正式提交可能使用账户配额或产生平台费用；具体按平台规则执行。提交成功后，保存代理返回的**集群别名、调度系统和完整作业号**，并查看申请资源、当前状态以及结果和日志位置。

“提交成功”表示调度器接受了任务，不表示已经开始计算。“排队”“挂起”“运行中”和“已结束”是不同状态；排队原因由代理查询解释。提交回应不明确时先核查，不要反复要求重新提交。

### 6. 查看进度、结果与取回文件

**查看进度：**

```text
请查看集群……上作业……的状态，解释等待或报错原因，暂不重新提交。
```

**检查结果：**

```text
请检查作业……是否完成，整理运行记录，并告诉我结果和日志在哪里。
```

**下载结果：**

```text
请把这次作业的结果下载到我指定的本机位置：……
```

正式提交的批处理作业通常由调度系统独立管理，关闭本地窗口一般不影响它；交互作业另当别论。对话结束后，代理不会自动持续回复进度。需要连续采样时，由作业内的采集脚本执行；以后凭集群别名和完整作业号可继续查询并补齐最终记录。

历史统计可能延迟或已过保留期。查不到作业不等于成功完成，代理会结合可获取的日志与输出说明已知结果和缺失证据。取回文件后应检查完整性；不会因下载完成就自动删除远端结果。

### 常见卡点

| 情况 | 下一步 |
|---|---|
| 找不到技能 | 检查三个技能是否安装完成；必要时重启 Codex，并显式调用通用入口 |
| SSH 可以连接，但查不到调度命令 | 让代理检查平台指定的登录节点和环境；不要在自己电脑安装调度器来代替远端配置 |
| 队列查询成功却没有作业 | 可能只是当前没有可见作业；与连接或查询报错不同 |
| 不知道账户、分区或队列 | 让代理先查询可用配置；缺少的权限信息向平台或管理员获取 |
| 作业一直等待 | 查询调度原因；不要用重复提交解决等待 |
| PBS 查询不到已结束的作业 | 历史记录可能未启用或已过期，结合保存的记录和日志继续检查 |
| 安装成功，但尚未有输入文件 | 技能安装不会产生计算输入；先准备软件所需的文件 |

## 看懂几个常用词

| 词语 | 可以怎样理解 |
|---|---|
| 集群／节点 | 一组计算机／其中用于计算的一台或一个资源单元 |
| 调度系统 | 管理任务排队和资源分配的服务，例如 Slurm、PBS |
| 分区／队列 | 提交任务时选择的资源或调度入口；两种系统的参数不能直接混用 |
| 计费账户／项目 | 任务使用哪份额度或归属哪个项目，与登录用户名不一定相同 |
| QoS | 部分集群的优先级和资源限制策略，是否需要由平台决定 |
| CPU／内存／walltime | 计算资源、运行时存储空间、允许的最长运行时间；walltime 不是预计完成时间 |
| MPI／线程 | 多个进程协同计算／一个进程内并行工作；具体方式由软件和平台决定 |
| 作业号／日志 | 调度器返回的任务标识／程序运行过程的文字记录 |

## 记录与清理

记录软件原始输出、调度状态、耗时、退出状态和可获取的 CPU/内存观测。软件支持时记录模型设置、网格、自由度和收敛过程；没有的指标保持未观测。多节点观测需要说明覆盖范围和汇总方法。

退出码为零或生成了结果文件，都不能单独证明计算成功。代理结合软件完成信息、调度终态及预期输出判断；物理正确性需另行验证。

先保存记录，再清理本次运行创建且已不用的临时文件。保留输入、结果、非空日志、提交脚本和要求保留的检查点。
