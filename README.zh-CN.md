# 软件 Slurm 作业提交与记录技能

[English](README.md)

本技能指导代理准备、提交、监控和记录 Slurm 集群上的软件作业，并根据实际软件、任务需求和集群支持的启动方式生成脚本。

## 环境与安装

### 在 Codex CLI 中安装

1. 在终端运行 `codex`，进入 Codex CLI。
2. 将下面这段请求粘贴到 Codex 对话中：

   ```text
   $skill-installer 安装这个技能：https://github.com/Raining-Sunshine/SAI-agent-job-submit-skill/tree/main/skills/software-slurm-run
   ```

3. 安装完成后，使用 `/skills` 查找 `software-slurm-run`，或者在下一条消息中调用：

   ```text
   $software-slurm-run 使用我已有的集群连接准备软件作业，提交前说明申请的资源。
   ```

上述请求在 Codex 对话中输入，不是 shell 命令。安装器会安装完整的技能文件夹，包括引用文档和元数据。如果技能没有显示，重启 Codex。参见 [Codex 官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

### 作业运行条件

需要具备：

- SSH 客户端，以及已经建立的集群连接。
- Slurm 使用权限、可用计费账户、分区，以及适用时的 QoS。
- 计算节点上可用的软件，以及软件需要的许可证。
- 为当前任务选定的可写存储空间。
- 分布式计算所需的兼容 MPI 环境。

使用软件支持的批处理接口。只有实际工作流需要时，才依赖额外解释器或 API。

## SSH 连接

在自己的终端中完成连接配置。SSH config 最小示例：

```sshconfig
Host cluster
    HostName <HOST>
    User <USER>
    Port <PORT>
    IdentityFile <KEY_FILE>
    IdentitiesOnly yes
```

密钥位置按自己的配置填写。首次连接和有口令密钥的解锁在自己的终端完成。代理使用已配置的别名：

```bash
ssh cluster 'squeue -u "$USER"'
```

代理无需读取密钥材料或许可证内容。

## 准备与提交

为当前任务提供输入文件、目标位置、软件启动方式、计费账户和资源需求。存储位置由实际任务决定，技能不规定目录层级。

上传完成后再准备作业。可以先使用临时文件名，传输完成后改名；软件要求文件扩展名时，保留其所需格式。保留输入原件，输出另存。

代理检查输入，准备独立运行，按照软件支持的参数生成提交脚本，并记录输入校验值、提交脚本、可获取的软件版本和申请资源。未经要求，不修改模型设置。

可以采用单节点、多节点、MPI、多线程或混合并行。节点数、任务数、每任务 CPU 数和内存按工作负载及集群配置选择。启动命令需与资源分配、软件和 MPI 环境匹配；增加资源不保证等比例提速。

仅准备作业不会提交。一次提交请求对应一个作业。代理检查脚本和调度请求，提交一次，保存作业号并核对状态。提交响应不明确时，先检查队列和已有提交证据，再决定后续操作。

## 监控与记录

记录调度状态、软件原始输出、耗时、退出状态、CPU 和内存观测。软件支持时，进一步记录模型设置、网格统计、自由度和收敛过程。

多节点任务需要覆盖整个资源分配。只在启动节点采集的数据不能代表整个作业；合并数据时保留节点、step 和时间信息。区分单核 CPU 使用率与整份配额利用率，以及单任务内存与作业汇总内存。

保留求解日志原始表头和参数上下文。线性残差、非线性误差和时间步具有不同含义；缺失指标保持未观测。

退出码为零只是证据之一。报告成功前，应结合调度终态、软件完成信息和预期输出检查。物理正确性需要另行开展科学验证。

## 完成与清理

确认作业进入终态后，刷新调度统计并保存最终记录。保留输入、结果、非空日志、提交脚本和复现信息。记录保存后，仅清理本次运行创建的临时文件；保留用户要求的检查点。

节点故障或强制终止可能打断收尾。先恢复可获取的观测，再清理，并明确说明无法核实的部分。
